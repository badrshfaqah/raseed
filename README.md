# رصيد (Raseed)

نظام ويب مالي بسيط وخفيف وسريع لإدارة الإيرادات والمصروفات للمشاريع والجهات، مع معرفة الرصيد الحالي لحظياً، وتقارير وإحصائيات، ومزامنة تلقائية مع Google Sheets.

## المميزات

- **معالج تثبيت** يعمل تلقائياً عند أول تشغيل (فحص السيرفر ← قاعدة البيانات ← إعدادات النظام ← حساب المدير ← التثبيت)، ويُعطَّل تلقائياً بعد اكتمال التثبيت.
- **لوحة تحكم** ببطاقات إجمالي الإيرادات والمصروفات والرصيد الحالي (أخضر للموجب، أحمر للسالب) وآخر العمليات.
- **إيرادات ومصروفات** مع تصنيفات وبنود مترابطة (اختيار التصنيف يعرض بنوده فقط).
- **كشف حساب** مع فلترة (من/إلى تاريخ، النوع، التصنيف، البند) وبحث وإجماليات.
- **إحصائيات** مع رسوم Chart.js (شهرية + توزيع المصروفات حسب التصنيف) وأكثر التصنيفات والبنود صرفاً.
- **مزامنة Google Sheets** عبر Service Account — قاعدة البيانات هي المصدر الأساسي، وفشل المزامنة لا يوقف الحفظ أبداً ويسجَّل في سجل المزامنة مع إمكانية إعادة المحاولة.
- **تصدير** Excel (XLSX) و CSV — الكل / الإيرادات فقط / المصروفات فقط / نتائج الفلترة الحالية.
- **استيراد من Excel/CSV** (للمدير): تنزيل قالب جاهز، تعبئته، ورفعه لإضافة الإيرادات والمصروفات دفعة واحدة — مع **إنشاء التصنيفات والبنود الجديدة تلقائياً**، ومعاينة كاملة قبل الحفظ تعرض الصفوف الصحيحة والأخطاء وما سيُنشأ.
- **نسخ احتياطي** SQL بضغطة واحدة، واستعادة من داخل النظام.
- **مستخدمون وصلاحيات**: مدير نظام + مستخدم (إدخال أو مشاهدة فقط).
- **واجهة عربية RTL** حديثة و Responsive بالكامل (الجداول تتحول لبطاقات على الجوال، بدون تمرير أفقي).

## المتطلبات

- PHP 8.0 أو أحدث مع امتدادات: `pdo_mysql`, `openssl`, `curl`, `json`, `mbstring` (و `zip` لتصدير XLSX — اختياري).
- MySQL 5.7+ / MariaDB 10.3+.
- أي استضافة مشتركة عادية (Apache مع `.htaccess`). لا حاجة إلى Composer أو Node أو أي أوامر سيرفر.

## التثبيت

1. ارفع الملفات إلى مجلد مستقل، مثل: `domain.com/raseed` (لن يؤثر على أي موقع WordPress بنفس الاستضافة).
2. أنشئ قاعدة بيانات MySQL فارغة ومستخدماً لها من لوحة الاستضافة.
3. افتح `domain.com/raseed` في المتصفح — سيحوّلك تلقائياً إلى معالج التثبيت.
4. أكمل الخطوات الخمس. بعد الانتهاء تُعطَّل صفحة التثبيت تلقائياً (لإعادة التثبيت احذف `config.php` يدوياً).

## إعداد مزامنة Google Sheets

1. من [Google Cloud Console](https://console.cloud.google.com) أنشئ مشروعاً وفعّل **Google Sheets API**.
2. أنشئ **Service Account** ونزّل مفتاح JSON الخاص به.
3. أنشئ ملف Google Sheets وشاركه مع بريد الحساب (`client_email` في ملف JSON) بصلاحية **تحرير**.
4. من **الإعدادات ← Google Sheets** داخل النظام: ألصق Sheet ID (من رابط الملف) ومحتوى ملف JSON، ثم اضغط **اختبار الاتصال وتجهيز ورقة العمل**.

كل عملية إضافة/تعديل/حذف تُزامَن تلقائياً، وتظهر نتيجتها في **سجل المزامنة**.

## تحديث النظام (رفع إصدار جديد)

بياناتك (المستخدمون، العمليات، الإعدادات) محفوظة في قاعدة البيانات لا في الملفات، وملف `config.php` مستبعَد من المستودع. لذلك التحديث بسيط:

1. خذ **نسخة احتياطية** من داخل النظام (النسخ الاحتياطي ← تنزيل).
2. **ارفع الملفات الجديدة فوق القديمة** (Overwrite) عبر FTP — سيبقى `config.php` كما هو تلقائياً لأنه غير موجود في الحزمة الجديدة.
3. إن كان التحديث يتضمن تغييراً في بنية الجداول، سيظهر تلقائياً **تنبيه للمدير** ورابط **«ترقية النظام»** → افتح `upgrade.php` واضغط «تطبيق التحديثات». هو يعدّل بنية الجداول فقط ولا يحذف أي بيانات ولا يلمس أي ملف PHP.

نظام الإصدارات: رقم بنية القاعدة محفوظ في `settings.db_version` مقابل الثابت `RASEED_DB_VERSION` في `includes/migrations.php`. لإضافة تغيير جدولي مستقبلي: ارفع `RASEED_DB_VERSION` وأضف جمل SQL في `raseed_migrations()` — لا حاجة لأي SQL يدوي على الاستضافة.

## بنية المشروع

```
raseed/
├── install/              معالج التثبيت (schema.php + index.php)
├── includes/             النواة: db, auth, functions, GoogleSheets, Xlsx, layout
├── assets/               CSS + JS
├── api/items.php         بنود التصنيف (JSON للنماذج)
├── logs/                 سجل الأخطاء (محمي)
├── *.php                 صفحات النظام
└── config.php            يُنشأ تلقائياً بواسطة معالج التثبيت (محمي بـ .htaccess)
```

## ملاحظات تقنية

- **بدون أي مكتبات خارجية على السيرفر**: مزامنة Google Sheets تتم عبر عميل خفيف مدمج (توقيع JWT بـ OpenSSL + cURL)، وتصدير Excel عبر كاتب XLSX أصلي مدمج (ZipArchive) بدل PhpSpreadsheet — للحفاظ على صغر حجم النظام وسرعته وسهولة تركيبه بدون Composer. مكتبات الواجهة (Bootstrap 5 RTL, Chart.js, Bootstrap Icons, خط Tajawal) تُحمَّل من CDN.
- **الحماية**:
  - جميع الاستعلامات عبر PDO Prepared Statements (لا حقن SQL)، وجميع المخرجات مهرّبة (لا XSS)، وجميع النماذج محمية بـ CSRF Token.
  - كلمات المرور مشفرة بـ `password_hash` (bcrypt)، مع مقارنة ثابتة التوقيت تمنع كشف أسماء المستخدمين.
  - **قفل محاولات الدخول**: بعد 5 محاولات فاشلة خلال 15 دقيقة (لنفس المستخدم أو نفس الـ IP) يُوقف الدخول مؤقتاً، مع إبطاء كل محاولة فاشلة.
  - **تحصين الجلسات**: ربط الجلسة ببصمة المتصفح، إنهاء تلقائي بعد 30 دقيقة خمول، تجديد دوري لمعرف الجلسة، و`use_strict_mode`.
  - **ترويسات أمنية** على كل صفحة: `Content-Security-Policy` بنظام **Nonce** (أي سكربت مُحقن لا يُنفَّذ حتى لو وُجدت ثغرة XSS)، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`، `Referrer-Policy`، `Permissions-Policy`، و`HSTS` عند العمل عبر HTTPS.
  - **حماية من حقن معادلات CSV**: الخلايا النصية التي تبدأ بمحارف المعادلات (`=` `+` `-` `@`) تُحيَّد قبل التصدير فلا ينفذها Excel.
  - **حدود مدخلات**: سقف أعلى للمبلغ، وطول أقصى للملاحظات (1000 حرف).
  - `config.php` و `includes/` و `logs/` محمية بـ `.htaccess` (مع `index.html` احتياطي للاستضافات غير Apache)، ويُنصح بحذف مجلد `install/` بعد اكتمال التثبيت.
- عمليات الحفظ تتم داخل Transactions لضمان سلامة البيانات، والأخطاء تُسجَّل في `logs/error.log`.
- الجداول: `users`, `categories`, `items`, `transactions`, `google_sheet_sync_logs`, `settings`.
